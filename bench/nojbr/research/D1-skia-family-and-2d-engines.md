## Notes

1. **Skia C API claim, stated as read from the Skia repo.** `google/skia` `main` contains no `include/c` directory [read-WF listing; confirmed by raw 404 on `include/c/sk_canvas.h`]. The long-lived C layer used by SkiaSharp is `include/c/*.h` + `src/c` in `mono/skia` branch `skiasharp` [measured: files return HTTP 200]. My local Skia fork checkout in the scratchpad (`skia-fork`, JetBrains/skia, HEAD 0eb44914, 2026-10-12) is a blob-less sparse clone whose `include/` holds only `BUILD.bazel`, `OWNERS`, `gpu` [measured], so it neither confirms nor refutes the C layer there; the `google/skia` evidence is what counts.
2. **Wayland without JBR is a presentation problem, not a drawing-library problem.** Skiko ties Linux to AWT/JAWT+GLX/X11 [measured]. Any Skia route that avoids this must create the EGL/Vulkan surface itself (GLFW via LWJGL, or direct libwayland-client through FFM), then hand it to Skia (Skija `DirectContext`/`BackendRenderTarget`, or a C shim `gr_direct_context_make_gl`/`_vulkan`) [inferred from API names]. Wayland-side items still unverified by me: whether the LWJGL-bundled GLFW is >= 3.4 with native Wayland; fractional scale; client-side decorations.
3. **Dependence on large companies.** Skia: Google. Skiko: JetBrains (and tracks a JetBrains Skia fork, so Skia changes reach us through JetBrains' cadence) [measured]. Skija: small org, Skia API break risk placed on the maintainer [read]. Blend2D/ThorVG/NanoVG/Vello/Pathfinder: no single big-company owner visible in READMEs, but small bus factors (Blend2D two copyright holders [read]; NanoVG one author, unmaintained [read]; ThorVG sponsored by LottieFiles with Canva/Godot/LVGL contributing [read-WF]; Linebender is a collective [read: Zulip-based governance, repo README]).
4. **Text-editor text needs** (ligatures in code fonts, emoji, fallback, rich rows) are all satisfied today only by the Skia/Skija/Skiko stack in this survey (Skija table lists Shaper and Paragraph classes [read]). Every other candidate needs us to add HarfBuzz (Old MIT [read: raw harfbuzz COPYING]) and FreeType (FTL/GPL dual [read: raw FTL.TXT is present]) plus a glyph atlas/cache. That is the "own renderer" route, not a library choice. Cost estimate: unknown, not measured.
5. **Not surveyed (honest gap):** Qt Quick/QCanvasPainter (only its NanoVG attribution seen), femtovg, Slint, Rive renderer, GPUI, Direct2D/CoreText per-platform native stacks, JavaFX Prism, Java2D with `sun.java2d.opengl`, AGG, Skia Graphite/Dawn state, SDL3 renderer. I did not check them; none is claimed here.
